# gb — Game Block

Скрипт для шкільних комп'ютерів на Windows 10/11, який блокує ігрові сайти, TikTok, Instagram і Twitch. Працює через системний файл `hosts`: заблокований сайт просто не відкривається в жодному браузері. Доступ до роутера не потрібен: достатньо один раз запустити скрипт на кожному комп'ютері, далі він оновлюється сам.

## Що потрібно

- **PowerShell від адміністратора.** Без цього всі скрипти, крім `find-games.ps1`, зупиняються з повідомленням `Run PowerShell as Administrator.`
- **Інтернет на час запуску.** Скрипти й списки завантажуються з GitHub (`raw.githubusercontent.com`).
- **Для блокування програм (AppLocker): Windows 10/11 Pro, Education або Enterprise.** На Home `block-apps.ps1` відмовиться працювати. Блокування сайтів працює на будь-якій редакції.
- **Учнівські акаунти без прав адміністратора.** Адмін може сам зняти будь-яке блокування.

Більше нічого встановлювати не треба. Команда `irm ... | iex` не залежить від Execution Policy: скрипт не зберігається у файл.

## Порядок роботи

**Один раз на кожному ПК** (PowerShell від адміністратора):

1. `irm https://raw.githubusercontent.com/VladislavSournine/gb/main/install-gb.ps1 | iex` встановлює команду `gb`.
2. `gb sites` блокує сайти. Далі список сайтів оновлюється сам.
3. `gb apps -AuditOnly`, потім `gb apps` блокують програми ([AppLocker](#блокування-програм-applocker)).

**Коли з'явилися нові ігри:**

1. `gb find -OutDir E:\` на ПК, де їх бачили.
2. Вставити вміст `apps-block-<ПК>.txt` у форму «Додати ігри» на GitHub ([як саме](#як-додати-знайдені-ігри-у-список)).
3. `gb apps` на кожному ПК. Програми, на відміну від сайтів, самі не оновлюються.

Сайти додаються в [`custom-block.txt`](custom-block.txt) на GitHub. Більше нічого робити не треба: ПК підхоплять зміни під час наступного ввімкнення або о 7:40.

## Коротка команда `gb`

Щоб не вставляти щоразу довгі команди, один раз на кожному ПК встанови `gb` (PowerShell від адміністратора):

```powershell
irm https://raw.githubusercontent.com/VladislavSournine/gb/main/install-gb.ps1 | iex
```

Далі в будь-якому вікні PowerShell від адміністратора:

| Команда | Що робить |
|---|---|
| `gb` | довідка |
| `gb sites` | заблокувати сайти й встановити автооновлення (те саме, що «Швидкий запуск» нижче) |
| `gb sites -Remove` | прибрати блокування сайтів |
| `gb apps -AuditOnly` | AppLocker у тестовому режимі |
| `gb apps` / `gb apps -Strict` | заблокувати програми |
| `gb apps -Undo` | відкат AppLocker на крок назад |
| `gb apps -Remove` | вимкнути всі правила AppLocker |
| `gb find -All -OutDir E:\` | знайти ігри |
| `gb uninstall` | прибрати саму команду `gb` (блокування лишаються) |

Усі параметри скриптів, описані нижче, працюють і через `gb`, наприклад `gb sites -Extra roblox.com,epicgames.com -NoAutoUpdate`.

Як це працює:
- `gb` щоразу завантажує **найновішу** версію скрипта з GitHub, тож зміни в репозиторії діють одразу, без перевстановлення. Без інтернету `gb` не працює.
- Встановлюються два файли: `C:\Program Files\SysTools\gb.ps1` і `C:\Windows\gb.cmd`. Писати в ці теки можуть лише адміністратори, тож учень не підмінить команду. Execution Policy змінювати не треба.
- Без прав адміністратора `gb` одразу зупиняється.
- Повторний запуск інсталятора оновлює `gb.ps1`. Потрібно лише тоді, коли змінився сам `gb.ps1`, а не інші скрипти.

| AppLocker: вимкнути всі правила | `gb apps -Remove` | `& ([scriptblock]::Create((irm https://raw.githubusercontent.com/VladislavSournine/gb/main/block-apps.ps1))) -Remove` |

## Швидкий запуск

1. Відкрий PowerShell **від адміністратора** (Win+X → «Термінал (адміністратор)»).
2. Встав команду (або `gb sites`, якщо `gb` встановлено):

   ```powershell
   irm https://raw.githubusercontent.com/VladislavSournine/gb/main/block-games.ps1 | iex
   ```

3. Зачекай, доки з'явиться зелений рядок `Done. Restart browsers to apply.`
4. Перезапусти браузери.

Перевірка: `ping friv.com` має відповідати з `0.0.0.0`.

## Що робить скрипт

- Завантажує два списки й об'єднує їх:
  - [UT1 games](https://raw.githubusercontent.com/olbat/ut1-blacklists/master/blacklists/games/domains) — ~33 тис. ігрових доменів, список підтримує Тулузький університет;
  - [`custom-block.txt`](custom-block.txt) — власний список: TikTok, Instagram, Twitch, піддомени Roblox. Його можна редагувати прямо на GitHub, і зміни потраплять на комп'ютер під час наступного запуску скрипта.
- Додає до кожного домену `www.`-варіант і записує все в `hosts` як `0.0.0.0` між мітками `GAME-BLOCK BEGIN/END`. Решту файлу `hosts` не чіпає.
- Вимикає «безпечний DNS» (DNS-over-HTTPS) у Chrome, Edge і Firefox через політики, щоб браузери не обходили `hosts`.
- Скидає кеш DNS.
- Встановлює задачу `GameBlock` у Планувальнику завдань (див. нижче).

Скрипт можна запускати повторно: старий блок замінюється новим, дублікатів не буде. Якщо список не завантажився, `hosts` лишається без змін.

## Автооновлення

Під час першого запуску скрипт створює задачу `GameBlock` у Планувальнику завдань. Вона працює від імені SYSTEM, і учень без прав адміністратора не може її вимкнути. Задача запускається:
- під час кожного завантаження Windows (через 1 хвилину після старту);
- щодня о 7:40, для комп'ютерів, які не перезавантажують. Якщо о 7:40 комп'ютер був вимкнений (ноутбук), пропущений запуск виконається, щойно його ввімкнуть.

Щоразу вона завантажує **найновішу** версію скрипта й обох списків з GitHub. Тому достатньо змінити `custom-block.txt` або скрипт у репозиторії, і зміни самі потраплять на всі комп'ютери. Якщо після старту мережі ще немає (ноутбук ще не підключився до Wi-Fi), задача повторює спробу до 10 разів з інтервалом 20 секунд, а потім перезапускається ще 3 рази кожні 10 хвилин. Без інтернету лишається останній завантажений список, тож блокування не знімається. Якщо список не змінився, `hosts` не перезаписується.

Журнал останнього запуску: `C:\ProgramData\GameBlock\last-run.log`.

Перевірити, що задача є: `Get-ScheduledTask GameBlock`. Запустити її вручну: `Start-ScheduledTask GameBlock`.

## Параметри

```powershell
$url = 'https://raw.githubusercontent.com/VladislavSournine/gb/main/block-games.ps1'

# повністю прибрати: блок, задачу, політики браузерів
& ([scriptblock]::Create((irm $url))) -Remove

# заблокувати один раз, без автооновлення
& ([scriptblock]::Create((irm $url))) -NoAutoUpdate

# додати домени лише на цьому комп'ютері (разово)
& ([scriptblock]::Create((irm $url))) -Extra roblox.com,epicgames.com -NoAutoUpdate
```

| Параметр | Що робить |
|---|---|
| `-Remove` | прибрати блок, задачу `GameBlock` і політики браузерів |
| `-NoAutoUpdate` | заблокувати без задачі (і видалити задачу, якщо вона була) |
| `-Extra` | додаткові домени (для постійних краще редагувати `custom-block.txt`) |
| `-ListUrl` | свої списки замість стандартних (масив URL, plain text, один домен на рядок) |
| `-NoWww` | не додавати `www.`-варіанти |
| `-SkipBrowserPolicy` | не змінювати політики браузерів |
| `-FromTask` | службовий: так скрипт запускає сама задача |

## Обмеження

- `hosts` не підтримує wildcard: піддомен, якого немає у списку, не заблокується. Такі піддомени додавай через `-Extra`.
- Якщо учень має права адміна, він може відредагувати `hosts`. Тому учнівські акаунти мають бути без адмін-прав.
- VPN і проксі-розширення обходять `hosts`.
- Оригінальний `hosts` зберігається один раз у `hosts.game-block.bak`.
- Задача щоразу виконує код із цього репозиторію від імені SYSTEM. Хто має доступ до репозиторію, той керує всіма комп'ютерами, тож тримай увімкненою двофакторну автентифікацію на GitHub.

# Блокування програм (AppLocker)

Окремо від сайтів: два скрипти, щоб знайти встановлені ігри та заблокувати їхній запуск. Працює на Windows 10/11 **Pro, Education, Enterprise**, на Home AppLocker немає. Усе запускається в PowerShell **від адміністратора**.

## 1. Знайти ігри: `find-games.ps1`

```powershell
irm https://raw.githubusercontent.com/VladislavSournine/gb/main/find-games.ps1 | iex
```

Скрипт нічого не змінює на комп'ютері, тільки шукає. Він перевіряє профілі всіх учнів (AppData, Робочий стіл, Завантаження, Документи), Program Files, папки `Games`/`SteamLibrary`/`Riot Games` на всіх дисках і програми з Microsoft Store.

Програма вважається грою, якщо:
- її назва, шлях або видавець схожі на гру чи лаунчер (Roblox, Minecraft, TLauncher, Steam, Epic, Riot, Genshin...);
- або поруч лежать файли ігрового рушія (`UnityPlayer.dll`, `GameAssembly.dll`, `steam_api64.dll`, Unreal `-Shipping.exe`, Godot `.pck`).

Так знаходяться навіть невідомі інді-ігри, скачані з itch.io чи з флешки.

На Робочому столі з'являться два файли (у назві ім'я комп'ютера):
- `games-<ПК>.csv` — повний список: що знайдено, де лежить, у якого учня, чим підписано;
- `apps-block-<ПК>.txt` — готові правила блокування для цих програм.

Параметри:
- `-OutDir E:\` — зберегти на флешку, щоб зібрати результати з усіх 20 комп'ютерів в одному місці;
- `-All` — показати ще й усі інші програми, які учні поставили у свій профіль без прав адміна;
- `-Pick` — відкрити вікно зі списком і позначити, що саме блокувати.

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/VladislavSournine/gb/main/find-games.ps1))) -OutDir E:\ -All
```

## 2. Список блокування: `apps-block.txt`

Звичайний текстовий файл у репозиторії, один рядок — одне правило:

```
path: %OSDRIVE%\Users\*\AppData\Local\Roblox\*          # папка (для будь-якого учня)
publisher: O=VALVE CORP., L=BELLEVUE, S=WASHINGTON, C=US | *   # усе, що підписав видавець
appx: CN=Microsoft Corporation, ... | Microsoft.MinecraftUWP # програма з Microsoft Store
allow: %OSDRIVE%\Users\*\Documents\UnityProjects\*      # ДОЗВОЛИТИ папку (лише для -Strict)
```

У файлі вже є Roblox, Minecraft Java/TLauncher, Steam, Epic, Riot, EA, Ubisoft, Battle.net і Xbox-ігри. Minecraft Education не блокується.

### Як додати знайдені ігри у список

`find-games.ps1` записує правила в `apps-block-<ПК>.txt` у тому самому форматі, що й `apps-block.txt`, тож їх можна просто скопіювати. **Самі вони нікуди не потрапляють:** `gb apps` бере правила лише з `apps-block.txt` на GitHub.

1. **Знайди ігри** на одному або кількох ПК:

   ```powershell
   gb find -OutDir E:\
   ```

   На флешці з'явиться `apps-block-<ПК>.txt` для кожного комп'ютера. Приклад:

   ```
   # [Game] Roblox (name: Roblox) users: kid1, kid2
   path: %OSDRIVE%\Users\*\AppData\Local\Roblox\*

   # [Game] Hollow Knight (engine: UnityPlayer.dll) users: kid3
   path: %OSDRIVE%\Users\*\Desktop\HollowKnight\*

   # [Social] BytedancePte.Ltd.TikTok (Microsoft Store package)
   appx: CN=..., O=..., C=US | BytedancePte.Ltd.TikTok
   ```

   Рядок з `#` — це коментар: що знайдено, чому скрипт вважає це грою, у яких учнів. Наступний рядок без `#` — саме правило.

2. **Переглянь і видали зайве.** Прибери правила для того, що блокувати не треба. Найчастіше це рядки `[UserApp]`: їх показує тільки `-All`, і серед них трапляються звичайні програми. Рядки `[Social]` (TikTok, Discord...) залиш або прибери — на свій розсуд. Учнівські збірки Unity (`[UnityProject]`) правила не мають, їх скрипт лише показує.

3. **Додай правила через форму на GitHub** (можна прямо зі шкільного ПК або з телефона):
   1. github.com → репозиторій → **Issues → New issue → «Додати ігри»**.
   2. Встав рядки з `apps-block-<ПК>.txt` у поле «Правила». Коментарі `#` теж можна вставити, вони допоможуть згадати, звідки правило.
   3. Натисни **Create**. За хвилину GitHub сам перевірить правила, допише нові в `apps-block.txt`, відповість в issue і закриє його.

   - Правила, які вже є в списку, пропускаються. Тож можна вставляти файли з різних ПК, не вичищаючи повтори.
   - Якщо хоч одне правило з помилкою (наприклад, просто `Roblox.exe` або `path: %WINDIR%\...`), нічого не додається. Issue лишається відкритим, а у відповіді буде список помилок. Виправ і створи нове issue.
   - Форма спрацьовує лише для власника репозиторію. Issue від інших людей ігноруються.
   - Інший спосіб: відкрити `apps-block.txt` на github.com → іконка олівця (Edit) → вставити рядки в кінець → **Commit changes**. Перевірки тоді немає.

4. **Застосуй на кожному ПК.** Сам AppLocker не оновлюється, на відміну від блокування сайтів. Тому після зміни списку запусти на кожному комп'ютері:

   ```powershell
   gb apps -AuditOnly   # спершу перевірити, що нічого зайвого не заблокується (журнал AppLocker)
   gb apps              # заблокувати
   ```

   Якщо в списку є рядок, якого скрипт не розуміє, він пропустить його з попередженням `Skipped: ...`, а решту правил застосує.

Що варто знати про правила:
- **`path: ...\Users\*\...`** діє на всіх учнів. `*` замість імені користувача скрипт підставляє сам.
- **`path: ...\Desktop\<Тека>\*`** прив'язане до назви теки. Учень може перейменувати теку, і гра запуститься. Від цього захищає `publisher:` (якщо гра підписана) або режим `-Strict`.
- **`publisher: ...`** скрипт пропонує, коли гра підписана видавцем. Таке правило діє, хоч куди перенеси файл.

## 3. Заблокувати: `block-apps.ps1`

Спочатку раджу тестовий режим: нічого не блокується, AppLocker лише записує в журнал, що **заблокував би**.

```powershell
$u = 'https://raw.githubusercontent.com/VladislavSournine/gb/main/block-apps.ps1'
& ([scriptblock]::Create((irm $u))) -AuditOnly
```

Журнал: Перегляд подій → Журнали програм і служб → Microsoft → Windows → AppLocker → EXE and DLL (подія 8003).

Коли все гаразд, вмикай блокування:

```powershell
irm https://raw.githubusercontent.com/VladislavSournine/gb/main/block-apps.ps1 | iex
```

| Режим | Що відбувається |
|---|---|
| за замовчуванням | працює все, **крім** програм зі списку |
| `-Strict` | учням дозволено лише Windows і Program Files. Усе, що учень сам поставив в AppData, Завантаження, на Робочий стіл чи запустив з флешки, блокується, разом зі списком. Адміністраторам дозволено все |
| `-AuditOnly` | нічого не блокується, лише журнал |
| `-RulesFile E:\apps-block.txt` | взяти правила з локального файлу, а не з GitHub |
| `-Remove` | вимкнути всі правила AppLocker |
| `-Undo` | відкат: повернути політику, яка була до останнього запуску скрипта. Кожен наступний `-Undo` — ще крок назад |
| `-BackupFile <файл>` | відновити політику з конкретного бекапу `C:\ProgramData\GameBlock\applocker-backup-*.xml` |

Що робить скрипт:
- зберігає попередню політику AppLocker у `C:\ProgramData\GameBlock\applocker-backup-*.xml`, а потім замінює її;
- закриває теку `C:\ProgramData\GameBlock` для всіх, крім адміністраторів і SYSTEM. Інакше учень міг би підкласти туди «бекап» з політикою «дозволити все»;
- вмикає службу Application Identity (`AppIDSvc`), без якої AppLocker не працює;
- завжди додає правило «дозволити всі підписані програми Store», бо без нього Windows блокує навіть «Параметри» і Калькулятор;
- відмовляється блокувати весь `%WINDIR%` або «всього Microsoft», щоб випадково не зламати систему.

### Відкат AppLocker

```powershell
$u = 'https://raw.githubusercontent.com/VladislavSournine/gb/main/block-apps.ps1'

# повернути політику, яка була до останнього запуску block-apps.ps1
& ([scriptblock]::Create((irm $u))) -Undo

# відновити з конкретного бекапу
& ([scriptblock]::Create((irm $u))) -BackupFile C:\ProgramData\GameBlock\applocker-backup-20261116-093000.xml

# вимкнути всі правила AppLocker
& ([scriptblock]::Create((irm $u))) -Remove
```

- **`-Undo`** працює як «скасувати»: кожен наступний `-Undo` відкочує ще на крок назад. Приклад: застосували звичайний режим, потім `-Strict`. Перший `-Undo` повертає звичайний режим, другий — стан до першого запуску.
- Використаний бекап перейменовується в `applocker-undone-*.xml`, а поточна політика перед відкатом зберігається як `applocker-before-undo-*.xml`. Нічого не губиться.
- `-Undo` відмовляється застосовувати бекап, якщо його створив не адміністратор: `... was not created by an administrator`. Таке буває, коли учень підклав файл ще до того, як тека була закрита. Видали цей файл і запусти `-Undo` ще раз.
- Якщо теку `C:\ProgramData\GameBlock` створив не адміністратор або це посилання, скрипт перейменовує її на `GameBlock.untrusted-<дата>` і створює нову. Попереднє попередження покаже нове ім'я. Старі бекапи лишаються в перейменованій теці: після перевірки їх можна відновити через `-BackupFile`.
- Перед застосуванням бекап перевіряється. Якщо файл зіпсований або це не політика AppLocker, нічого не зміниться.
- `-Remove` не те саме, що `-Undo`. Він вимикає всі правила AppLocker, навіть ті, що були налаштовані до цього скрипта.
- Бекапи без `-Undo` можна подивитися в `C:\ProgramData\GameBlock` (відкривати від адміністратора).

Якщо після відкату програма все ще не запускається або, навпаки, досі блокується, вийди з акаунта чи перезавантаж комп'ютер.

### Уроки Unity

- **Звичайний режим Unity не зачіпає.** Unity Editor, Unity Hub і збірки учнів запускаються як завжди, бо блокується лише те, що є в списку.
- **`find-games.ps1` не пропонує блокувати Unity.** Він пропускає Unity Editor, Unity Hub, Visual Studio, VS Code, JetBrains і Python. Учнівські збірки він впізнає за `ProjectSettings\ProjectVersion.txt` у батьківській папці й позначає `UnityProject` без правила блокування.
- **Видавця Unity Technologies заблокувати цілком не можна.** `block-apps.ps1` відмовиться так само, як для Microsoft.
- **У режимі `-Strict` потрібні дозволи.** Редактор стоїть у Program Files і працює, а от збірки (`Build\гра.exe`) лежать у профілі учня й блокуються. Для цього в `apps-block.txt` є рядки `allow:`. Домовтеся з учнями тримати проєкти в одній папці, наприклад `Документи\UnityProjects`.

Обмеження:
- Правила `path:` прив'язані до папки: учень може перенести непідписану гру в іншу папку. Від цього захищає `-Strict` (будь-яка папка профілю заблокована) або правило `publisher:` (діє незалежно від папки).
- Якщо учень має права адміністратора, він може вимкнути AppLocker. Учнівські акаунти мають бути без адмін-прав.
- Блок діє для всіх, включно з учителями. Щоб тимчасово запустити заблоковану програму, використай `-Remove`.
